🧹 NLP preprocessing P1–P9
agents/nlp/preprocess.py
  • P1 Assemble diagnosis + treatment + notes
  • P2 Normalise: NFKC, quotes, "5mg"→"5 mg", spaces
  • P3 Expand 41 abbreviations: k/c/o, HTN, T2DM, RTA…
  • P4 De-identify: name, hospital, policy, phone, ID → [PLACEHOLDERS]
  • P5 Split into numbered sentences S1…Sn
  • P6 Tag entities with a clinical gazetteer
  • P7 Negation (NegEx scope, 8 tokens): "no h/o DM"
  • P8 Durations: "since 2018" → 8 y, "x 4 yrs" → 4 y
  • P9 Token budget (≈4 chars/token, 1,200 max)
🧠 LLM layer P10–P13
agents/nlp/prompts.py · agents/llm.py · agents/nlp/parsing.py
  • P10 Prompt builder: system rules + allowed values + 1 worked example + de-identified, numbered sentences + request date
  • PII gate GUARD: blocks the call if any original identifier is in the prompt
  • Ollama client: POST /api/generate · model llama3.2 · format = JSON schema · temperature 0 · seed 42 · num_ctx 4096 · SHA-256 response cache
  • P11 Parse: strip fences / chatter, extract first JSON object
  • P12 Validate against the schema → on error send a repair prompt (max 2) → else fall back to rule-based facts
  • P13 Ground each condition in its cited sentence (drop negated / unsupported = hallucination guard), then compare with rule extractor → disagreements go to the Critic

agents/guardrails.py

End-to-end flow: 1hospital submits request → 2UI calls run(claim) → 3Planner writes the plan → 4documents checked → 5notes cleaned P1–P9 → 6LLM extracts facts P10–P13 behind the PII gate, validated, grounded and cross-checked → 7MLC / FIR if accident → 8policy, clauses and tariff fetched → 9eligibility rules → 10payable waterfall (if eligible) → 11Critic re-checks, may send back to 10 → 12decision + letter (LLM polish, faithfulness check) → 13medical officer if escalated → 14result, letter and audit record shown in the UI
