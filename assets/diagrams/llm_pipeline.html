How text is prepared for, sent to, and checked after the LLM

Pipeline run inside the Document Intake agent (tasks preprocess_text and extract_facts) · live example: request PA-2026-0107, angioplasty, notes full of abbreviations plus a name and phone number
1 · Prepare the text — runs locally, before any LLM
P1
Assemble
Collect diagnosis, proposed treatment and the doctor's free-text notes as three sections.
Notes: “Mrs Lata Kulkarni, 64F, c/o exertional chest pain x 3 mths. K/c/o HTN since 2018 on Tab. Amlodipine 5mg once daily. T2DM x 4 yrs on Tab. Metformin 50…”
→
P2
Normalise
Unicode NFKC, straight quotes, dashes, number–unit spacing, collapse whitespace.
“Amlodipine 5mg once daily” → “Amlodipine 5 mg once daily”
→
P3
Expand abbreviations
Dictionary of 45 clinical short forms, case-aware word boundaries. Here: 16 expansions.
K/c/o HTN → Known case of hypertension
T2DM x 4 yrs → type 2 diabetes mellitus for 4 years
CAG · LAD · PTCA · DES · Tab. → full words
→
P4
De-identify (PII)
Patient name, hospital, policy / claim no., phone, e-mail, ID numbers → placeholders. Map kept locally.
Mrs Lata Kulkarni → Mrs [PATIENT]
Attendant contact 9000000001 → [PHONE_1]
→
P5
Segment sentences
Split on sentence punctuation (protecting Dr., Mrs., e.g.) and number them S1…Sn.
S4: Known case of hypertension since 2018 on Tablet Amlodipine 5 mg once …
S5: Type 2 diabetes mellitus for 4 years on Tablet Metformin 500 mg twice…
↓
2 · Understand the text and build the prompt
P6
Tag clinical entities
Longest-match gazetteer: conditions, procedures, drugs, tests, flags (cosmetic, accident, declared).
CONDITION: hypertension, Type 2 diabetes mellitus
PROCEDURE: percutaneous transluminal coronary angioplasty, drug-elutin…
MEDICATION: Amlodipine, Metformin
→
P7
Detect negation
NegEx-style: trigger words (no, not, denies, without, no history of) negate entities in the next 8 tokens until 'but' / ';'.
PA-0111: “No history of diabetes mellitus/hypertension/asthma.”
→ NEGATED: diabetes mellitus, hypertension, asthma
→
P8
Normalise durations
'since YYYY' (vs request date), 'for / x N years|months', 'N years ago' → years; attached to the nearest condition.
hypertension → 8 y; Type 2 diabetes mellitus → 4 y
→
P9
Token budget
≈4 characters per token (Llama BPE). If the notes exceed 1,200 tokens, low-value sentences are dropped first.
~162 tokens of 1200 → nothing dropped
→
P10
Build prompt
System rules + allowed values + 1 worked example + numbered, de-identified sentences + request date + JSON schema.
SYSTEM: 7 extraction rules (no guessing, ignore negated…)
USER: ### Allowed values · ### Example · ### Task
Request date: 2026-10-10 · Patient: [PATIENT], 64, F · S1…S8
↓
3 · Inside the LLM runtime — Ollama → llama.cpp → Meta Llama 3.2 3B Instruct
GATE
PII gate
Before the request leaves the app, every original identifier is searched for in the final prompt. Any hit blocks the call.
pass: “Lata Kulkarni”, “9000000001” not in prompt
→
L1
HTTP request to Ollama
POST /api/generate with system + prompt + JSON schema in `format`; options: temperature 0, seed 42, num_ctx 4096, num_predict 512. Ollama wraps it in the Llama 3 chat template.
<|start_header_id|>system<|end_header_id|> rules… <|eot_id|>
<|start_header_id|>user<|end_header_id|> ### Task …
→
L2
Tokenize
Byte-pair-encoding tokenizer with a 128,256-entry vocabulary turns the text into token IDs; long medical words split into several sub-word tokens.
prompt → ~631 token IDs* (window 4,096 of the model's 128K)
→
L3
Transformer forward pass
Token embeddings (3,072-d) → 28 decoder layers: grouped-query self-attention (24 heads, 8 KV heads), RoPE positions, SwiGLU MLP. 4-bit Q4_K_M weights (2.0 GB) on llama.cpp, CPU or GPU, KV cache reused per token.
Meta Llama 3.2 3B Instruct · open weights
→
L4
Constrained decoding
For each step the model scores all 128,256 tokens; a grammar built from the JSON schema masks every token that would break the schema; temperature 0 picks the top token (greedy). Repeat until the JSON closes.
only valid next pieces allowed, e.g. after "procedure_key": → one of the 10 enum values
→
L5
Detokenize and respond
Token IDs → text. Ollama returns the response plus prompt_eval_count, eval_count and timings, which the app logs.
69 output tokens* → JSON text
↓
4 · Verify what comes back before any agent uses it
P11
Parse
Strip ``` fences and chatter, pull out the first balanced JSON object, map synonyms ('high blood pressure' → hypertension).
{"procedure_key": "angioplasty", "chronic_conditions": [{"condition": "hypertension", "duration_years": 8, "evidence_sentence": 4}, {"condition": "diabetes", "duration_y…
→
P12
Validate
Check types, enums and required keys against the schema. Errors → repair prompt listing the errors (max 2) → else rule-based facts.
errors: 0 · attempts: 1 · fallback: no
→
P13
Ground and cross-check
Each condition must be stated, not negated, in the sentence it cites (else dropped as a hallucination). Then compare field-by-field with the rule extractor.
hypertension S4 → grounded; diabetes S5 → grounded
LLM vs rules: 5/5 fields agree
→
OUT
Facts → shared state
Validated facts go to the blackboard; disagreements become Critic findings; the Executor uses them for PED and exclusion rules.
procedure: angioplasty · hypertension 8 y, diabetes 4 y · accident: false
→
LTR
Same path for the letter
Decision agent: template letter → de-identify → PII gate → LLM polish (plain text) → re-identify → faithfulness check: identical amounts, clause numbers and placeholders, else the template is sent.
same ₹ amounts ✓ · same clause nos. ✓ · same [PLACEHOLDERS] ✓ → LLM letter accepted
